## 被测形态（务必与生产区分）

- 服务：`crates/sdkwork-routes-memory-open-api/examples/mem0_platform_server.rs`
  —— **线级开发 harness**，不是部署形态。单进程 axum，进程内 SQLite fixture
  （`new_seeded_in_memory_store`），无 PostgreSQL、无 Redis、无多副本。
- 鉴权：`SDKWORK_IAM_ALLOW_DEV_AUTH_FALLBACK=true` + claim 形式 fixture API key
  （tenant 100001 / user 2001）。
- 数据规模：mem0 兼容空间 `365155957134815232` 内 48 条种子记录
  （经 `POST /v3/memories/add/` 写入，内容覆盖驱动查询词池）。
- 负载参数：`--scenarios retrieval,mem0-batch --duration-secs 60 --concurrency 8`；
  检索体 topK=8、contextBudgetTokens=4096、查询词池 24 词随机 2-4 词组合；
  mem0 批量按 `SDKWORK_LOAD_MEM0_ID_POOL` 的 48 个真实 memory_id 循环批 50 条更新。
- 宿主：Windows 11（10.0.26200）开发机，Node 24.11.1 驱动，Rust dev profile
  （未优化构建）。

## 与发布门禁的关系

`docs/releases/README.md` 要求的部署级 load/soak 证据（PostgreSQL、多副本、共享
Redis、生产规模数据、与 99.9% 可用性目标同窗）**仍待归档**；本文件证明的是协议面
（SDKWork 信封、幂等命令头、mem0 wire 批量写）在真实 HTTP 上按预算工作，以及驱动
本身的端到端可用。
